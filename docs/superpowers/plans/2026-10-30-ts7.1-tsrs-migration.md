# TS 7.1 移行 + tsrs ロードマップ 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Weekly-Task-Board を TypeScript 7.1(beta)へ安全に移行し、tsrs(Rust ポート)採用への昇格条件付きロードマップを確立する。現行の tsgo 7.0 環境(CI・本番)は最後まで無変更で維持する。

**Architecture:** 併存(parallel install)戦略。`typescript-next` という npm エイリアスで `typescript@beta`(7.1.0-beta)を追加導入し、既存の `tsgo`(native-preview 7.0 ピン留め)と `typescript@5.9.3` は一切変更しない。3 つのコンパイラを別スクリプトで並行実行して診断差分を検証し、CI ではまず `continue-on-error: true` で情報収集、安定後に昇格する。

**Tech Stack:** TypeScript 7.1.0-beta (mainline Go compiler) / tsgo (@typescript/native-preview 7.0.0-dev.20260421.2) / tsrs 0.20.1-ts7.1.0-beta (oxc-project, Rust port) / Vitest 5 / Vite 8 / GitHub Actions

**Spec:** 本計画の背景仕様は下記「背景」セクション + `MIGRATION_PROGRESS.md`(2026-04-24 時点でハイブリッド移行完了・tsgo type-check グリーン)。バージョン管理ルールは `CLAUDE.md` に従う。

| tsc フォールバック | `typescript@5.9.3`(`compile-hybrid.sh` も 5.9 に依存) | `typescript` latest = **7.0.2**(安定版)、beta = **7.1.0-beta**、next = 7.1.0-dev |

tsrs は 2026-10 前後に Cloudflare/VoidZero が公開した TypeScript 7 型チェッカーの Rust ポート(oxc-project/tsrs)で、**TS 7.1 beta をターゲット**にしている。したがって「7.1 への移行」が「tsrs 採用」の前提条件になる。

## Global Constraints

- **現行環境の無変更:** `type-check`(tsgo 7.0 ピン留め)・`typescript@^5.9.3`・`compile-hybrid*.sh`・`tsconfig.json` の compilerOptions は本計画の全タスクで変更しない。7.1 / tsrs 用の変更はすべて新規スクリプト・新設定として追加する
- すべての作業は `main` から切ったブランチで行い、PR 経由でマージする。`main` / `dev` への直接 push はしない
- GitHub Actions の `uses:` はコミット SHA ピン留め(security-base ルール)。新規 step は `run:` のみで `uses:` を追加しないことで回避
- Conventional Commits(feat: / fix: / ci: / docs: / chore:)
- プッシュごとにパッチバージョンを上げる:`src/app/init.ts` の `APP_VERSION` + `public/sw.js` の `CACHE_NAME`(CLAUDE.md ルール)
- tsrs は prerelease を **exact ピン留め**(先頭 `^` を付けない)
- `ts7/` 実験ディレクトリは本計画の対象外(触らない)

## Review Focus

1. **npm エイリアスの bin 衝突** — `typescript-next`(alias)と `typescript`(5.9)は同じ `tsc` bin を持つため `node_modules/.bin/tsc` がどちらを指すか不定になる。期待される挙動: どちらも `.bin` 経由で呼ばず、直接パス `node node_modules/<name>/bin/tsc` で呼ぶことで影響を排除。→ Task 2 の Step 4 で `.bin/tsc` の指す先と 5.9 の動作をテストで固定
2. **7.1 beta の診断差分で CI が赤化** — 7.1 beta は tsgo 7.0 と完全同一の診断を保証しない。期待される挙動: 7.1 チェックは `continue-on-error: true` で始め、差分ゼロを確認してから必須化する。→ Task 3 でローカル差分ゼロをテスト、Task 4 の CI は最初から許容モード
3. **tsrs が別の診断を出す** — tsrs は tsc の互換実装だが `strict` / `noUncheckedIndexedAccess` 等での差異が報告されている。期待される挙動: tsrs の実行結果を記録し、差分があってもデフォルト type-check には影響しない。→ Task 5 の Step 3 で差分記録テスト
4. **5.9 tsc 依存の退路** — `compile-hybrid*.sh` は `node_modules/.bin/tsc`(5.9)を直接参照する。期待される挙動: `typescript@5.9.3` は削除しないので手動ビルドスクリプトは壊れない。→ Task 2 の Step 4 で 5.9 生存確認テスト
5. **package-lock 更新による CI キャッシュ** — ci.yml のキャッシュキーは `hashFiles('**/package-lock.json')` のため alias 追加で自動的に新キーになる。追加対処は不要だが、Task 4 の CI 実行で npm install が成功することを確認する
